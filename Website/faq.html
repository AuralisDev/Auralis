Quick answers

Questions? Answered.

Helpful answers for inviting Auralis, finding commands, setting up the dashboard and understanding live website statistics.

Why does Login with Discord send me to a setup page?

The public site is hosted on GitHub Pages, which only serves static files. A secure Discord OAuth login needs the Auralis Node.js backend to receive the callback, verify the OAuth state, create a session and load your servers. Set apiBase in Website/config.js to the deployed backend HTTPS URL once you have one.

Can GitHub host the Discord bot and backend for free?

GitHub Pages can host the public frontend for free, but it cannot run a permanent Node.js process or OAuth callback. GitHub Actions is for jobs that start and finish; it should not be used as a 24/7 Discord gateway process. You need a separate bot/backend host.

Why is the server count blank or zero?

The installed-server count comes from the running bot's guild index and cannot be known from static website files alone. Until the backend is deployed and the bot has connected and synchronized its server list, the website shows the metric as unavailable rather than inventing a number.

Does the public server directory control the total server count?

No. Total servers counts all servers in the bot's current guild index. Public communities counts only servers that are opted into the public directory. Those numbers should normally be different.

Which OAuth scopes does the website login need?

Use identify and guilds for the website login. Do not use connections as a replacement for guilds. The OAuth redirect URL must be the exact backend callback URL configured in the Discord Developer Portal.

Will my server's settings affect other servers?

Dashboard settings are keyed by Discord server ID. The signed-in person must own the server or have Administrator / Manage Server permission, and the backend checks access on protected requests.

Why can a command page show a 404 after I add the file?

GitHub Pages serves the last successful deployment, not just the current repository files. Check the repository's Actions tab, rerun “Build and deploy Auralis Website” and confirm that Settings → Pages uses GitHub Actions as the publishing source. This project's build validation now checks that expected pages exist before deployment.

Are the preview switches on the homepage live controls?

No. The module preview is a visual illustration. Real configuration switches and save actions run in the authenticated dashboard and require a working backend and bot.

Still setting up?

Follow the deployment instructions and verify your Discord OAuth redirect before trying to sign in.
